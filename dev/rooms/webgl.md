## 원칙 (지금 게임과 따로)
- 새 렌더러는 **별도 파일 `src/gl.js`** + game.js에는 최소한의 연결만 (렌더러 고르기 · 그리기 명령 넘기기). 다른 작업과 충돌을 줄이려고 game.js 수정은 몇 군데로 묶고 주석 `// GL:` 표시.
- 본서버 기본값 **꺼짐**. 켜는 법: 테스트 페이지(DEMO) 또는 설정 [새 그래픽(시험)] · URL `?gl=1` · localStorage `aden_gl=1`. 꺼져 있으면 지금과 100% 같은 그림·성능(회귀 없음 — 테스트로 확인).
- WebGL을 못 쓰는 기기(WebGL2 없음·컨텍스트 잃음)면 자동으로 지금 Canvas2D로 돌아감.
- 봇 호스트 모드(BOTHOST · work/bothost에 있음)는 그림을 안 그리므로 무관 — gl.js가 BOTHOST일 때 아무것도 안 하게.

## 0단계 (이번 보조 작업자): 설계 확정 + 시제품 + 30명 벤치마크
1. **구조 결정** (둘 중 하나를 실측으로 고르고 이유를 적기):
   - (A) 기록 방식: drawWorld가 쓰는 Canvas2D 컨텍스트를 '기록용 가짜 컨텍스트'로 바꿔 drawImage/변환/알파/합성 모드를 명령 목록으로 모으고 GL이 한 번에 그림. 경로·그라데이션·글자 같은 비-이미지 명령은 (a) 그 객체 단위로 오프스크린에 그려 텍스처로 캐시하거나 (b) 순서를 지키는 2D 오버레이로 넘김.
   - (B) 명시적 그리기 목록: 바닥·캐릭터·몹·이펙트를 game.js에서 '스프라이트 목록'(이미지·원본 사각형·위치·크기·알파·블렌드·깊이)으로 내보내고 gl.js가 정렬·배치해 그림.
   - 판단 기준: 지금 그림과 같은 결과(픽셀 비교) · 앞으로 콘텐츠 추가 때 손이 덜 가는 쪽 · 성능.
2. **시제품**: 정한 구조로 바닥(타일·바닥 캔버스) + 캐릭터·다른 유저·몹(스프라이트 시트) + 그림자 + 이름표·HP 막대를 GL로 그리기. 화면 해상도·DPR·줌·카메라·피격 번쩍임·투명도·좌우 반전이 지금과 같게. 나머지(이펙트·코드 그림 몹·UI 글자)는 우선 지금 방식 그대로 위/아래에 겹쳐 그려도 됨(순서가 크게 틀리지 않게).
3. **30명 벤치마크** `dev/tests/gl_bench.js`: 한 화면에 캐릭터(다른 유저 대역 또는 필드 봇) 30명 + 몹 20~40 + 타격 이펙트가 계속 나는 장면(화룡의 둥지 2구역 등)을 만들고, GL 끔/켬의 프레임 시간(평균·p90·최악)과 CPU 프로파일(그리기 비율)을 비교. 헤드리스는 GPU가 없으니 `--use-angle=swiftshader`·`--enable-unsafe-swiftshader` 같은 소프트웨어 GL로 돌려 상대 비교만(절대값은 실제 PC와 다름을 적기).
4. **정확도 테스트** `dev/tests/gl_parity.js`: 같은 장면을 끔/켬으로 찍어 화면 차이를 수치로(평균 픽셀 차이·차이 큰 영역) + 스크린샷 `dev/out/gl_off.png`·`gl_on.png`·`gl_diff.png`.
5. 기존 테스트 몇 개(polygacha·dream·fieldbot2 등)를 GL 꺼진 상태로 돌려 회귀 없음 확인.
6. `dev/rooms/webgl.md`에 결정·구조·남은 단계(① 이펙트 빛·블룸 ② 코드 그림 몹 ③ UI ④ 기본값 켜기 기준) 정리.
