# 기록(감사 기록) 시스템 — 카드 tasks/auditlog · 갈래 work/auditlog

## 맥락 (11/6)
프로듀서 친구 캐릭터 '해골'(Lv53 기사, 시작 며칠)이 +18 반역자의 방패 · +13 커츠의 티셔츠 · +8 반지 2개 등 확률상 불가능한 장비를 가짐.
게임은 서버 없이 클라이언트가 Firestore `users/{uid}/chars/{직업}`에 20초마다 저장 → '실패 직후 강제 종료로 되돌리기'나 저장 조작이 가능한데, 강화·거래 기록이 서버에 없어 확인할 길이 없었음.
→ 사건마다 Firestore `audit` 컬렉션에 문서를 **새로 만들기만** 하는 기록을 붙임. (되돌리기 자체를 막는 건 따로 `work/nosavescum` — 이 갈래는 강화 결과 흐름을 바꾸지 않고 `audit('en', …)` 호출만 덧붙임)

## 결정
- 문서 `audit/{uid_시각36_난수}` 필드: `u`(uid) `n`(캐릭터 이름) `c`(직업) `k`(종류) `t`(ms) `v`(GAME_VER) `d`(내용 JSON) — CLOUD가 모든 값을 문자열로 저장.
- 기록하는 사건(`k`): `en` 강화(안전 강화를 넘는 시도 결과 전부 · 안전 구간은 결과 +7 이상 · 저주는 +7 이상에서) · `bless` 축복 부여 성공/실패 · `chg` 장비/장신구 변경 주문서 · `gacha` 변신 카드·마법인형 뽑기/마일리지/재뽑기/합성의 영웅·전설, 빛바랜 벨트, 연금술 영웅·전설 · `trade` 거래 완료 · `adm` 운영자 지급/회수/골드/레벨/펫 받음 · `code` 복구 코드로 받은 것 · `snap` 상태 사진(접속 15초 뒤 + 30분마다) · `gold` 1분 안에 설명 안 되는 골드 +200만.
- 계정 서버 로그인일 때만 (데모·이 기기·봇 호스트·운영자 모드는 아무것도 안 함). 큐 최대 200 · 5초마다(강화·거래·지급은 바로) · 1분 60개까지 · 인터넷 오류 30초 뒤 같은 id로 · 거절(403 = 규칙 없음) 콘솔 경고 1번 뒤 5분 쉼(문서마다 3번) · 창 닫을 때 남은 것 keepalive.
- 운영자 창 [살펴보기] 머리에 [기록] → `audit` 최근 300건(또는 1000건) 읽어 그 사람(uid · 예전 버전이면 이름) 것만 시간순 표(한국 시간). 사진 두 장 사이에 기록 없이 +7 이상 장비가 생기면 빨간 '설명 안 되는 변화' 줄 (증발 기록 뒤에도 그대로면 '되돌리기 의심'). 읽기는 버튼 누를 때만.
- [살펴보기] 수상한 점: 규칙상 나올 수 없는 강화(무기 +10 · 장신구 +8 · 방어구 +15 · 할로윈 모자 +9 · 가호 +8 초과 · 강화 못 하는 아이템의 강화 수치) 빨강, 확률 1000분의 1보다 드문 수치 주황 + '안전 +4 위로 12~14번 연속 성공 · 약 91만~478만분의 1'(축복~일반 주문서).

## 규칙 한 줄 (프로듀서가 Firebase 콘솔 → Firestore → 규칙에 직접 추가 · server/bothost/README.md ④처럼)

match /audit/{id} { allow create: if request.auth != null && request.resource.data.u == request.auth.uid; allow read: if request.auth != null; }
