## 계획
### 1단계 · 감지하고 막기 (서버 프로그램 추가 없음)
- 기록 시스템(`work/auditlog`) · Firestore 규칙 `match /audit/{id} { allow create: if request.auth != null && request.resource.data.u == request.auth.uid; allow read: if request.auth != null; }`
- 차단 목록: 저장 규칙에 `!exists(/databases/$(database)/documents/bans/$(request.auth.uid))` (서버가 막으므로 클라이언트를 고쳐도 못 피함)
- 봇 호스트 자동 감지: 접속 정보(presence)를 2분마다 비교 → 골드·경험치 급증 · 규칙상 없는 강화 · 레벨 점프 → 운영자 알림·기록
- 하루 1번 저장 백업(되돌리기용 · 만들기만 되는 컬렉션)
- 게임 안 방어: 상점 가격·확률표 얼리기 · 저장 직전 규칙 검사(가격 1원 같은 건 저장 거부)
### 2단계 · 서버만 저장 (2D·고닷 공통)
- 게임은 '저장해 줘'만 보내고 서버가 이전 저장과 비교·검사 후 Firestore에 씀(클라이언트 쓰기 금지 규칙 · 서버는 Admin SDK).
- 상점 구매 = 서버 가격표로 계산 · 강화·뽑기 = 서버가 굴림 · 골드·경험치 = 시간당 최대치 넘으면 거부 · 새 고강 장비·전설은 기록된 사건(드랍·구매·강화·뽑기·거래·운영자 지급)으로만.
- 서울 AWS 서버에 작은 Node 프로그램(또는 Firebase Cloud Functions · Blaze 요금제 필요). Firebase 서비스 계정 키는 프로듀서가 직접 만들어 서버에 넣음(우리는 키를 다루지 않음).
- **고닷 쪽도 같은 구멍**(메모리 수정 도구) → 3D 방은 저장 기능을 만들 때 Firestore 직접 쓰기 대신 이 서버 API를 쓰게.
